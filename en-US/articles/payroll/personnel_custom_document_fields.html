    Overview

    Personnel Custom Document Fields is a ELVA customization integrated with Dynamics 365 Business Central.

    Purpose: To allow customers to create their own variables that are used in HR document templates.

    Assumptions and limitations

    Must be installed: Latvian Payroll and Personnel Latvian Payroll.

    What is Personnel Custom Document Fields?

    In printed HR documents (orders, employment contracts, internal documents), variables or placeholders are used — e.g., EMPLOYEENAME, POSITION. The system automatically replaces them with the current employee data values.

    This solution allows you to independently create new variables, whose values come from fields on the employee, position, department, or employment contract card.

    How to find

    1. Press Tell Me (search, Alt+Q).
    2. Type Document Custom Fields.
    3. Open the page result.

    Usage Scenarios

    1. Scenario — Position Name in English

    Situation: The customer has added a field Description ENG (English name) to positions. The printed orders require the variable POSITIONNAMEENG.

    Steps:

    1. Open Document Custom Fields.

    2. Click New (or enter a new row in the list).

    3. Fill in the fields:

      Field Value
      Code POSITIONNAMEENG
      Description Position Name ENG
      Reference Employee
      Source Record Position
      Source Field Description ENG
      Enabled ✓

    4. Open the document template and insert POSITIONNAMEENG in the desired location.

    Result: When the personnel order is printed, the system replaces POSITIONNAMEENG with the English position name from the employee's active position card.

    2. Scenario — Name of the Department in another language

    Situation: The customer has added a field Description ENG (English name) to departments. The labour contract requires the variable DEPTNAMEENG.

    Steps:

    1. Open Document Custom Fields → New.

    2. Fill in the fields:

      Field Value
      Code DEPTNAMEENG
      Description Dept Name ENG
      Reference Labour Contract
      Source Record Department
      Source Field Description ENG
      Enabled ✓

    3. Insert DEPTNAMEENG in the template.

    Result: When the labour contract is printed, the system looks up the employee's current position, retrieves the department from it, and returns the value of the Description ENG field.

    3. Scenario — Direct Labour Contract Field Value

    Situation: The labour contract card has a nice field Contract Language Code. The template requires the variable LCLANGCODE.

    Steps:

    1. Open Document Custom Fields → New.

    2. Fill in the fields:

      Field Value
      Code LCLANGCODE
      Description Contract Language
      Reference Labour Contract
      Source Record Labour Contract
      Source Field Contract Language Code
      Enabled ✓

    3. Insert LCLANGCODE in the template.

    4. Scenario — Employee Custom Field

    Situation: The employee card has a custom field Tax ID. The business card or internal notice requires the variable TAXID.

    Steps:

    1. Open Document Custom Fields → New.

    2. Fill in the fields:

      Field Value
      Code TAXID
      Description Tax ID
      Reference Employee
      Source Record Employee
      Source Field Tax ID
      Enabled ✓

    5. Scenario — Temporary Disabling of a Variable

    Situation: The variable POSITIONNAMEENG is temporarily not needed (for example, while the data is not yet maintained), but you do not want to delete the setting.

    Steps:

    1. Find the code POSITIONNAMEENG in Document Custom Fields.
    2. Clear the checkmark in the Enabled field.

    Result: The document will be printed, but the placeholder will remain unfilled (it will be printed as blank). After the data is prepared, check Enabled again.

    Case Endings (Additional Option)

    If the template requires a value in different grammatical cases, activate the Use Case Endings field and specify the Gender.

    Then, use the case prefix before the code in the template:

    Prefix Case
    N_ Nominative
    G_ Genitive
    D_ Dative
    A_ Accusative
    V_ Vocative
    I_ Instrumental
    L_ Locative

    Example: D_POSITIONNAMEENG — position name in dative case.

    Frequently Asked Questions

    Question: The field selection list in the Source Field column is empty.
    Answer: First, save the row to register the Source Record. Lookup relies on the saved Source Table Number.

    Question: The variable is printed as POSITIONNAMEENG (not replaced).
    Answer: Check:

    • The row exists and the Enabled column is checked.
    • The Source Field Number is filled (see the Source Field Name column).
    • The Reference matches the document type where the variable is used.

    Question: Can fields from other tables be used (not Employees/Position/Dept/LC)?
    Answer: No — this PTE only supports the four tables mentioned above. For more complex cases, a custom event subscriber is required.
